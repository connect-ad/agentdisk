# Test pass — deletion lifecycle, 22 September 2026

What to click, what should happen, and what it means if it doesn't.

Covers the ten deletion tasks plus the `staff` → `admin` rename and the
`securepanel` move. **Entitlements are not in this pass** — plan numbers exist
but nothing enforces them yet, so creating fifty agents on Free is expected to
work.

**Before you start.** Dev's database was rebuilt, so it is empty. Every test
below assumes you have signed up first (T2). Deletion is real now: both sweeps
are enabled and hourly, and the console's run-now button erases bytes
immediately.

## A. The things most likely to be broken

Do these first. Each one has a known failure mode that would look like
something else.

### T1 — Console sign-in
`securepanel-dev.agentdisk.io` → sign in with Google as `kernelv5@gmail.com`.

**Expect:** you land on Overview.

**If you get a clean login then a 403**, the Firebase domain is right and the
`admin_users` role is wrong. The migration seeded `super_admin`, which no
longer exists; I corrected the live row to `admin`, and this is the check.

**If the Google popup errors**, the authorized domain did not take.

### T2 — Sign up fresh
`app-dev.agentdisk.io` → sign up with an email you can receive at.

**Expect:** you land in a workspace created for you.

### T3 — Admin Accounts is reachable
Console → nav → **Admin Accounts**.

**Expect:** it is in the sidebar and opens.

**If it is missing**, the nav role collapse regressed. It was hidden from
everybody after the rename, because the nav still ranked
`support < admin < super_admin` while every operator is now `admin`.

## B. Workspace deletion

### T4 — The dialog says what actually happens
Dashboard → Settings → Danger zone → Delete workspace. **Read it, do not
confirm yet.**

**Expect three statements:**
- *Now, and permanently* — keys, agents, webhooks, share links, members, structure
- *In 7 days* — the files themselves
- *No restore*, and *email support to have it erased sooner*

**If it says "All files, agents, and API keys are permanently removed"**, the
old copy is still deployed. That sentence has been false since deferral landed.

### T5 — You cannot delete your only workspace
With one workspace, try to delete it.

**Expect:** refused, telling you to create another first.

### T6 — Deleting really does destroy the credentials
Create a second workspace, mint an API key in it, then delete that workspace.

**Expect:** the key stops working immediately (try it against
`api-dev.agentdisk.io/v1/whoami`). The files are queued, not gone — T10 shows
them.

## C. Account deletion and coming back

This is the sequence that proves the two re-join defects are fixed. **Use a
throwaway address**, because it genuinely deletes.

### T7 — Close your own account
Dashboard, signed in as the account owner → close the account, typing your
email to confirm.

**Expect:** it succeeds and you are signed out. If you had a Stripe
subscription, it is cancelled and the saved card detached.

### T8 — The address is still held during the window
Immediately try to sign up again with the same address.

**Expect:** refused. The address is deliberately held for seven days so we can
still email you — inside a recovery window you should be recovering, not
starting over.

**If it lets you sign up immediately**, the scrub is happening too early and
the deletion emails will have nowhere to go.

### T9 — And released afterwards
Console → **Deletions** → run the sweep now, then retry the signup.

**Expect:** the signup now succeeds, landing you in a **new, empty** workspace.
Nothing from the old account is restored.

**If it still refuses**, the address was never released — this was the defect
that locked people out of their own email address permanently.

## D. The console

### T10 — Deletions screen
Console → **Deletions**.

**Expect:**
- **Waiting** — files, bytes, how many are due now, oldest entry
- **Accounts** — counted separately from files
- **Recent runs** — the cron's rows say `cron`; yours will say your email

### T11 — Run-now is recorded
Run the sweep with a reason.

**Expect:** a new row naming *you*, not `cron`. Then Console → **Audit Log** →
a `deletions.run` entry with your reason.

**If the run is anonymous**, the audit discipline is not being inherited.

### T12 — A stalled sweep is visible
Note the **Oldest entry** date.

**Expect:** it moves as the queue drains. A date that stops moving is how a
stopped sweep shows itself — a count alone would read as "nothing to do".

## E. Claim links

### T13 — Provision and preview
Call `POST /v1/workspaces` unauthenticated (Turnstile-gated) to get a claim
URL, then open it **signed out**.

**Expect:** file count, size, agent name, expiry — no sign-in needed to look.

### T14 — A claimed link is indistinguishable from a fake one
Claim it. Then open the same URL again. Then open
`app-dev.agentdisk.io/claim/tok_obviouslyfake`.

**Expect:** both show the *same* "not valid" message. Neither says
"already claimed".

**If the claimed one says something different**, the oracle is back: this route
takes no credential, so a distinguishable answer tells anybody guessing tokens
which guesses named a real workspace.

### T15 — Claim Links console
Console → **Claim Links**.

**Expect:** four filters — All / Unclaimed / Claimed / **Due for deletion** —
search by workspace ID or token hash, and an attempts count per link.

### T16 — The history answers "who else has had this"
Click the attempts count on the link you claimed.

**Expect:** a timeline — your preview, your claim, and the second refused
attempt from T14, each with its IP.

**Expect to see a hash, never a token.** Only the hash was ever stored, which
is what lets support confirm *which* link was used without being able to use
it.

### T17 — Link and workspace expire together
Not clickable — provision a sandbox and check the preview's `expiresAt` and
`deletesAt`.

**Expect:** both seven days from creation. They used to be 30 and 7, so for
three weeks a valid link pointed at something already deleted.

## F. Copy

### T18 — Privacy policy
`app-dev.agentdisk.io/privacy` → clause 12.

**Expect:** a single file is erased **immediately**, no recycle bin; a
workspace or account erases files after **seven days**; invoices kept seven
years.

**If it says files "enter a recoverable state"** or "roughly 30 days", the old
text is live. Both were false.

### T19 — Export is not promised
Same page, clause 13.

**Expect:** it tells you to download your files before deleting. It must not
promise a packaged export — there is no endpoint and no delivery path.

### T20 — Settings → Privacy agrees
Dashboard → Settings → Privacy.

**Expect:** the same retention story as T18. `Legal.jsx` is authoritative where
they disagree.
